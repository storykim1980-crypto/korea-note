# 모바일 메뉴 오류 수정 및 검증 — 2026-10-12

## 재현한 문제

1. 기존 코드는 `data-jump-filter`가 있는 한국문화/한국어 링크만 메뉴를 닫았다. 식문화·뷰티·여행·편집방침 링크는 이동 후에도 `aria-expanded=true`, `.is-open` 상태였다. Chromium과 WebKit 모두에서 재현했다. 고정 메뉴 하단은 약 577px였으며, 이동한 본문이 그 뒤에 가려졌다.
2. 메뉴 높이에 화면 기준 제한/스크롤 처리가 없었다.
3. 추가 터치 검증에서 일본어 402/412px 화면의 헤더 버튼이 오른쪽으로 밀려, 햄버거 터치를 저장 버튼이 가로채는 현상을 재현했다.

## 수정

- 모든 메뉴 항목에서 같은 열기/닫기 함수를 사용한다. 표시 상태, aria-expanded 및 일본어/영어 접근성 이름을 함께 갱신한다.
- 같은 페이지 항목은 메뉴를 먼저 닫고 목적지로 이동한다. 제목으로 키보드 포커스를 이동하며 닫힌 메뉴 안에 포커스가 남지 않는다.
- 실제 고정 헤더 높이 + 16px를 이동 여백으로 사용한다. 긴 부드러운 이동과 모바일 포커스 변경의 충돌을 피하기 위해 메뉴 선택 이동은 즉시 처리한다.
- visualViewport 높이와 헤더 위치로 메뉴 가용 높이를 계산하고 메뉴 안쪽 스크롤을 제공한다. 마지막 언어 항목도 접근할 수 있다.
- 주소창 등 화면 높이만 바뀌면 메뉴를 유지하고 높이를 갱신한다. 화면 너비가 바뀌는 회전/크기 변경에서는 닫는다.
- Escape, 바깥 클릭, 페이지 이동 및 뒤로 돌아올 때의 닫힘 상태를 통일한다.
- 760px 이하에서 브랜드/보조문구 배치를 정리하고 헤더 버튼 3개를 각각 44px 터치 영역으로 고정했다. 화면 밖으로 밀리지 않는지 검사한다.

## 최종 브라우저 검증

전용 스크립트: `research/qa_mobile_navigation.cjs`
결과: `research/mobile-navigation-results.json`

- 엔진: Playwright Chromium / WebKit
- 언어: 일본어 / 영어
- 화면: 320×480, 360×800, 384×832, 390×844, 393×852, 402×874, 412×915, 430×932, 440×956, 844×390, 915×412
- 2개 엔진 × 2개 언어 × 11개 크기 = **44개 상태**
- 모든 내부 메뉴 항목 선택, 메뉴 닫힘, 목적지 가림, 포커스, 메뉴 글자 32px 확대, 마지막 메뉴 접근, Escape, 바깥 클릭, 회전, 높이만 변경하는 동작 등 **440개 검사 통과**
- 기존 22개 경로 × 6개 폭 = **132개 회귀 조합 통과**
- Axe WCAG 2.1 A/AA **28개 상태에서 위반 0건**
- 검색·필터·저장·체크리스트 기능 스모크 통과
- Chromium/WebKit에서 압축 해제 파일의 일본어→영어 메뉴 링크 직접 선택 성공
- WebKit/Chromium 모바일 메뉴 열림/목적지 화면 캡처 검토
- 정적 QA 통과: 254개 내부 링크, 119개 외부 링크 인스턴스

## 중요한 한계

이 검사는 모바일 터치·뷰포트 모의 검사다. 실제 Galaxy S26 시리즈, Samsung Internet 앱, 실제 iPhone 또는 실제 Safari 앱을 사용한 실기기 검사는 수행하지 않았다. 화면 크기는 일반적인 테스트 범위이지 특정 최신 모델의 공식 사양 인증이 아니다. OS 글꼴, 브라우저 설정, 주소창, 화면 확대, 실기기 입력 방식에 따라 추가 검증이 필요하다. 자동 접근성 검사는 인증이 아니다.

## 소유자의 최종 실기기 확인

새 ZIP 전체를 새 폴더에 풀거나 공개 파일 전체를 교체한 뒤 이전 탭/캐시가 아닌 새 버전을 연다.

1. 세로 화면에서 메뉴 열기 → 식문화/뷰티/여행/편집방침을 각각 선택한다.
2. 메뉴가 즉시 닫히고 해당 제목이 헤더 아래에 보이는지 확인한다.
3. 가로 화면에서 메뉴 내부를 내려 맨 아래 언어 전환을 선택한다.
4. 화면 글자를 크게 설정하고 동일하게 확인한다.
5. 일본어/영어에서 반복한다.

남은 오류를 신고할 때 모델명, 브라우저명·버전, URL 또는 파일 열기 방식, 화면 확대 설정 및 문제 화면을 함께 기록한다. 실제 배포는 수행하지 않았다.

## 재실행

공개 빌드를 `http://127.0.0.1:4173`에서 제공하고, Playwright의 chromium/webkit 및 OS 의존성을 설치한다.

```sh
node research/qa_mobile_navigation.cjs
```

별도 폴더에 Playwright를 설치한 경우 NODE_PATH를 해당 node_modules 경로로 설정한다. 이 스크립트와 결과는 내부 연구 자료이며 공개 배포 ZIP에 포함되지 않는다.
